## 📁 Folder structure

- **hosts/** - One directory per machine. Each `default.nix` imports what that host needs.
  - **common/core/** - Modules every host imports. If it is not for all hosts, it does not belong here.
  - **common/optional/** - Modules a host opts into (Docker, desktop, ...).
- **home/santi/** - [home-manager](https://github.com/nix-community/home-manager) configuration, same `common/{core,optional}` split. `<host>.nix` picks what each machine gets.
- **flake.nix** - Inputs (pinned in `flake.lock`) and one `nixosConfigurations.<host>` per machine.

The layout follows the [Misterio77](https://github.com/Misterio77/nix-config) / [EmergentMind](https://github.com/EmergentMind/nix-config) convention. Hosts only import; there are no custom `enable` options or frameworks on top of flakes.

## 🖥️ Hosts

| Host | Hardware | Role |
|------|----------|------|
| `tinyx` | Lenovo ThinkCentre M720q, i5-9400T, 8 GB | Headless homelab: Docker, Tailscale, Btrfs on NVMe + SATA |

Disk layouts are declared with [disko](https://github.com/nix-community/disko) in `hosts/<host>/disko.nix`. `hardware-configuration.nix` is generated by `nixos-generate-config --no-filesystems` and never edited by hand.

## 🔨 Applying changes

The repository lives in `~/nix-config` on each host and [nh](https://github.com/nix-community/nh) knows where to find it:

```bash
nh os switch
```

This builds `nixosConfigurations.$(hostname)`, shows a diff of what changes, activates it and adds a boot entry. To try a change without touching the bootloader (a reboot undoes it):

```bash
nh os test
```

Update all inputs and apply:

```bash
nix flake update && nh os switch
```

Garbage collection runs weekly through `programs.nh.clean`, keeping the last 5 generations or anything newer than 7 days. Rollback from the systemd-boot menu, or with `sudo nixos-rebuild switch --rollback`.

## 📦 Adding things

Try a program without installing it:

```bash
nix shell nixpkgs#ncdu
```

To install it, edit the config. Prefer a module when one exists (`programs.<x>.enable`, `services.<x>.enable`); fall back to `environment.systemPackages` for plain packages. System-level things go in `hosts/<host>/default.nix`, user-level things in `home/santi/`.

New files must be `git add`ed before building. A flake only sees tracked files.

## 🔐 Secrets

Nothing secret is committed. Hosts read secrets from `/etc/secrets/` (mode 600, outside the Nix store), which is provisioned during installation. `secrets/` is gitignored as a safety net.

## 💬 Commit messages

[Conventional Commits](https://www.conventionalcommits.org/), English, one line, with a scope:

```
feat(tinyx): enable nix-ld for vscode remote server
fix(network): use public nameservers and disable magicdns override
docs(nixos): rewrite comments in english and drop noise
```
